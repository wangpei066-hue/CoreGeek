# 规则核对（Python P0）

以下“官方明确”指当前提供的 v1.0 文档明文；不是判题器运行验证。代码现状见 current_audit.md。全部游戏规则均尚无官方对局实测，不能依据本地 HTTP 200 宣布通过。

## 计分与胜负

- 【官方明确】总分为任务+击杀+生存。完整任务：奖励积分 + 5×标准回合数/(完成回合−接取回合)，标准回合数为超时回合数；部分完成：奖励积分×正确字段数/全部字段数。金币为任务金币奖励×通过率。来源：任务书第五章、第六章。
- 【官方明确】小/中/大/BOSS 击杀分分别 1/2/4/10；生存分按 day=1..10 累加 10×day×存活系数，基地被毁当天及以后系数 0。来源：任务书4.7.2、第六章。
- 【官方明确】双方异常均达5次、到1300回合或双方基地均毁结束。先后被毁则先毁者负；同时被毁按积分，相同为平；双方存活按积分。上下半场换边，两场均胜者胜，否则各胜一场时比分数总和；胜/平/负积3/1/0。来源：任务书第七章。
- 【尚未确认】完成回合差为0、取整、共享击杀归属、半场一方存活和一方达到异常上限等边缘情形的完整判定实现。

## 昼夜、起点与换边

- 【官方明确】一天白天70回合、夜晚60回合，共10天1300回合；同时调度。机器人夜晚首回合出现，次日白天首回合清除；新闻每天白天首回合发布。来源：任务书4.2、4.7、4.8。
- 【官方明确】下半场双方互换位置；接口给出 challenger/defender 阵营及单位 ID 分配。来源：任务书第三章、第七章；接口文档1.3。
- 【尚未确认】roundNo 从0还是1起算、重启进程与否、换边时回合/ID/日志/state/任务技能重置边界。接口只将 roundNo 定义为“当前回合数”，不能据此写固定取模公式。来源：接口文档1.1；全文未见重置协议。

## 建造区、成本与移动

- 【官方明确】地图41×32，原点左下；蓝区仅武器、黄区仅围墙；矿不在建造区刷新。基地2×2，pos 为左上角。来源：任务书4.1；接口文档1.3.1。
- 【尚未确认】精确可建造格集合：文档依赖远程示意图，mapInfo.zones 仅列中立元素，未给可建造区字段。前轮尝试读取5张远程图片均失败，未获得图像内容，不据基地坐标猜范围。来源：任务书4.1及插图；接口文档1.2。
- 【官方明确】初始75金币、1开拓者2工人1基地。武器25金币/座，三种合计同时最多3座，新建level1，已有武器可覆盖；围墙消耗石头1，拆除不返还。仅工人白天在一格内建造。来源：任务书4.4、4.5.1、4.5.3。
- 【官方明确】切比雪夫距离；8方向移动一格，可穿两个相邻障碍物的对角。建筑、角色、机器人、中立单位、任务点、矿区阻挡；争用同格和两角色交换位置等碰撞会中断移动。来源：任务书4.1、4.5.4。
- 【官方明确】开拓者HP200/背包40，工人HP220/背包100；阵亡后次日白天开始后20回合可在基地复活，背包保留。来源：任务书4.5.2。

## 动作及待机

- 【官方明确】每角色每回合至多一条；动作全集为 move、attack、sell、buy、build、remove、acceptTask、submitAnswer、summonTreasure、use、drop、collect。来源：任务书4.4；接口文档2.2–2.3。
- 【官方明确】move/build/remove/collect 需要单目标；攻击传目标数组和 controllerId；sell/buy 指定 name，num 默认1；acceptTask 无额外参数；submitAnswer 用 taskAnswer；召唤用 targetPos 和 item；use/drop 指定 name，部分 use 需要坐标。来源：接口文档2.2–2.3。
- 【官方明确】采集/拆除仅工人；采集每回合一个矿，一矿10次后消失下回合刷新，不足多人平分时每工人仍得一个；出售和购买在相应商人一格内；采集在矿一格内。来源：任务书4.1、4.4。
- 【尚未确认】没有 wait/idle 动作码；“至多一条”允许不发角色指令是合理解释，但空 roleCommandMap 是否由判题器接受为待机仍须实测。当前 P0 固定空响应来自用户要求，非官方待机验证。

## 武器与物品

- 【官方明确】只有夜间可攻击，角色需在武器一格内操控，一角色同时一座。武器攻击先于机器人移动，伤害回合末统一结算。来源：任务书4.4；接口文档2.2。
- 【官方明确】加特林level1/2/3射程3/5/7、每颗10伤害，目标同90°锥，每弹命中路径最近机器人；电磁射程6/8/10，能量10/20/30沿弹道扣除实际伤害；火箭射程10/15/全图，每弹中心20、周围8格10、可叠加，3回合冷却。武器HP1000/1500/2000。来源：任务书4.5.1、4.5.4。
- 【官方明确】接口要求加特林/火箭目标位置数与等级相同，电磁一个；Role.cooldown 表示剩余冷却。来源：接口文档1.3.1、2.2。
- 【冲突/尚未确认】request.txt 的level1加特林射程4、电磁7、火箭2147483647，与任务书不同；样例缺若干新字段，不能作为权威参数。攻击指令示例以武器ID为key、controllerId为角色ID，待真实请求/反馈核验；建筑遮挡弹道的完整算法未给出。
- 【官方明确】武器/基地升级券100、150；围墙券20、30；目标一格内使用，升级回满血，非法/满级不消耗券。修墙包10、药10、眩晕100（3×3五回合）、炸弹100（3×3伤害100）；召唤令20/30/100/200，作用对方下夜、每天最多10张。任务用品样例每件15，清单可变化；商店物品不能退售。来源：任务书4.6.3。

## 任务、答案、LLM、沙盒

- 【官方明确】推理/长上下文通过新闻，自进化通过己方任务点；只有开拓者接任务；完成、超时、离开一格范围或死亡结束，结束后30回合刷新，任务总数有限；timeoutRounds 超时按已提交最高通过率答案结算。来源：任务书第五章；接口文档1.3.2。
- 【冲突/尚未确认】任务书4.6.2“处于任一格即可领取”与4.1任务点阻挡、4.4一格内领取的文字应结合官方反馈澄清，不能据此进入任务点占位。
- 【官方明确】taskAnswer 是 String；phaseTask 是已领取任务原文。来源：接口文档1.1、2.2。
- 【尚未确认】答案字符串内部是否 JSON、字段名/嵌套、大小写、精度、列表顺序与部分通过规范；样例只有 xxx。不能将任意 dict 直接当 taskAnswer 或认定存在通用 schema。
- 【官方明确】每游戏日LLM限3次，首回合重置；自进化任务接取至结束期间豁免且不计入日额度；prompt 请求、llmResp 次回合结果。来源：接口文档1.1、1.7、2.1。
- 【官方明确】独立沙盒可执行shell/Python且无外网；executeCmd 仅任务期间使用，本回合执行最多15秒，结果下次请求 lastCmdResult：exitCode、TIMEOUT、JUDGER_ERROR，超过64KB追加TRUNCATED；沙盒故障/命令超时不计队伍异常。来源：任务书5.3；接口文档1.1、2.1。
- 【官方明确】宝藏唯一；合法召唤不管成功均消耗物品，非法不消耗；物品集合不能多/少、无序；结果0未探测/非法、1成功、2无宝藏或未开启、3物品错、4已空；同回合双方成功均得奖励。来源：任务书5.2；接口文档1.1、2.3。

## 异常与提交

- 【官方明确】连接超过10秒、发请求后5秒无响应、响应格式错误、指令缺字段/无法识别计异常；累计5次停止调度，代码退出不重拉；合法动作因碰撞或攻击无目标执行失败不计异常。来源：任务书第八章。
- 【官方明确】errors码0未知、1任务超时、2答案错误、3网络、4指令、5LLM超限。不能将全部错误码等同队伍异常计数。来源：接口文档1.7；任务书第八章。
- 【官方明确】HTTP服务监听0.0.0.0，端口由系统传入；文档启动例为 bash run.sh port。来源：接口文档开头。
- 【用户确认】官方Python SDK入口为POST /、JSON对象、callback(json_data)返回dict，Flask转JSON。本轮按此实现，未独立取得发布包版本。
- 【官方明确】官方比赛 Python 版本为 3.11.10（用户核对《编译运行环境说明》确认）；该文档未说明依赖包版本、沙盒其他限制。来源：用户提供的《编译运行环境说明》核对结果。
- 【尚未确认】依赖包版本、提交目录/压缩包、run.sh是否仍必需、平台启动命令及限制；《编译运行环境说明》未覆盖这些项。
