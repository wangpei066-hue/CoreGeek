# 当前策略全表

本文描述 **现在代码实际会怎么走**，不是任务书原文。几何选址、回合取模、时限缓冲都是策略参数；建造格是否合法以判题器反馈为准。对照规则请看 `docs/rules_verified.md`。

入口：`V1Strategy.decide`（`src/agent/brain.py`）。主代码还分布在 `opening.py`、`economy.py`、`tactics.py`、`world_intel.py`、`treasure.py`、`task_solver.py`。

## 1. 每回合流水线

1. 保留新闻相关决策事件，其余本回合重写。
2. `begin_round`：吸收官方新闻/民间传闻；白天清掉「本夜见过威胁」；记录迎敌墙是否被拆；重置当天召唤限额与战术购买集合。
3. `learn_from_last_round`：建造失败按原因冷却。占位 2 回合，原因不明 5 回合，累计 3 次不明或描述像非法才 30 回合；缺石头/金币不封格子。
4. 分路：
   - `0 ≤ round_no < 70` 且有基地 → `plan_opening`（第一天白天；`cycle = round_no % 130`）
   - `cycle ≥ 70` 起停止开局远程经济，走 `plan_night`（无怪不能作为继续裸奔采矿/买券的理由）
   - 其它白天 → `plan_day`
   - 夜晚 → `plan_night`；见过本夜威胁后连续空窗达到试探外出阈值，才改走白天决策。当前刷怪立即撤销外出。未达阈值时只允许炮旁就近补正面墙/维修。有敌人立刻切夜间战斗。
5. 近敌且低血（≤30 或低于满血 15%）且有药：紧急 `use Medicine`。没有可靠伤害数据，日志叫「低血紧急治疗」，不称为下一击致死。
6. 输出前 `resolve_actor_conflicts`：按实际执行角色去重。普通动作占用角色 id；炮击占用 `controllerId`。紧急治疗选中后，丢掉该角色负责的炮击及其它冲突动作。只有最终发出的指令进入 `last_sent_command`。
7. 空闲且没在操炮的工人/开拓者：半血以下且有药才 `use Medicine`（普通自救，仍排最后）。
8. `_filter_valid` 丢掉：非工人的 `build/remove/collect`，非开拓者的 `acceptTask/submitAnswer`，以及本地字段校验失败的指令。

每角色每回合至多一条指令。`buy` / 建武器会扣本回合预算副本，超支则取消该指令。夜战 `attack` 挂在 **武器 id** 上，`controllerId` 是操控者；只改 `commands[角色id]` 不会自动覆盖炮击。

昼夜假设：一天 70 昼 + 60 夜，模 130。`roundNo` 从 0 还是 1 起算未经官方确认，边界回合可能偏一拍。

## 2. 角色能做什么

编制：1 开拓者 + 2 工人 + 1 基地。武器目标 **两门火箭炮 + 一门电磁炮**，每座 25 金。

| 动作 | 工人 | 开拓者 |
| --- | --- | --- |
| `collect` / `build` / `remove` | 可以 | 本地直接丢弃 |
| `acceptTask` / `submitAnswer` | 本地丢弃 | 可以 |
| `buy` / `sell` / `use` / `drop` / `move` / 夜战操炮 | 可以 | 可以 |
| 背包转交 | 官方没有此接口 | 官方没有此接口 |

满血（任务书表，策略自救用）：工人 220，开拓者 200；墙/炮 1/2/3 级 1000/1500/2000；基地 1500/3000/4500。

血量低于满血 50% 且背包有药 → `use Medicine`（回满，无需坐标）。路过武器商店、没药、金币够、背包有空 → 顺手买药（10 金），不专门跑一趟。

寻路：8 方向等代价，同回合预留格互斥。接近墙缺口走院子内侧，不从外侧贴墙。己方寻路不把外层诱敌开口当通道。临时被队友挡住时，会忽略可移动角色再寻一次，避免空转。

## 3. 院子、炮位、墙线

这些都是候选几何，不是官方蓝/黄区。靠地图边缘时墙线收缩到地图内。

**进攻方向（用户确认的刷新，不是任务书）**：基地在地图左半 → 敌人从右来；在右半 → 从左来。换边后按实际坐标再算。

**院子**：基地外扩约 2 格（`WALL_MARGIN=2`）的矩形内部。后方不封死，作为己方通道。

**三门武器位置**（`weapon_slots`，与武器种类无关，只按槽位排布）

1. 院子最后一排（远离进攻方向）上下两侧各一门  
2. 第三门放到另一侧再靠前一格，给迎敌墙内侧留通道  

格子被基地占格或已有建筑占住则跳过；三个槽都不可用时，在院子空位里兜底。

**墙**

- 内层（`primary_wall_plan`）：迎敌正面整列 + 侧翼延伸到后排武器列，后方开口。建造顺序先正面、再外层、再侧翼。  
- 外层（`wall_ring` 多出来的那一列）：再往前两格，中部留一格口。地图边缘放不下第二层则退化为单层。  
- 外层准入（`outer_wall_ready`）：内层完整、墙和三门炮都至少二级、墙血量 ≥80%。  
- 按天截断内层数量（`staged_wall_plan`）：第 0 天约 8 段，第 1 天约 12 段，之后铺满内层。天数 = `round_no // 130`。  
- 建某格前 `safe_wall`：建完后三人还能回到各自炮位、外面的人还能进院子、工人还能去商店/石矿、开拓者还能去任务点。否则换下一格。  
- 工人站在施工格上会先挪到邻格再 `build`。墙消耗背包 1 个石头。

## 4. 道具任务（买券、修墙、升墙、升基地）

两段式，挂在 `worker_item_jobs`（工人和开拓者共用这个字典）：

1. 背包没有该道具 → 去武器商店 `buy`；背包满则先 `drop` 铜/铁/石（不丢券和药）。  
2. 有道具 → 走到目标建筑一格内 `use`；发出后等下一回合结果确认再清任务。  
3. 目标建筑没了就释放任务。金币不够：武器券任务 **保留并继续筹资**；其它任务释放。  
4. 旧存档里未买的基地券，若还有武器/墙可升，会让位。

**新开任务优先级**（`maybe_start_shop_item_job`）：未满 2 级的武器 > 三门炮都到 2 级后升一次基地 > 升墙 > 武器 2→3 级 > 其余基地升级 > 紧急修墙。未买到手的修墙会让位于尚未到 2 级的武器。三炮二级后的首次升基地不让位于三级武器。同一目标不会被两人重复锁。

**升级会回满血**：任务书 4.6.3 写明「武器、围墙、基地升级后建筑将恢复到满血状态」。因此受损但还能升级的墙优先用升级券，不先买修复包。

**修墙（`use WallFixer`，10 金）**：只在墙**即将被摧毁**且已不能再升级（已 3 级）时用，而且背包里已经有修复包才派，不再专门跑商店排队买。即将摧毁：近敌（射程 3）两回合伤害就能打掉，或无近敌时血量 ≤80 / 低于满血 15%。高压破口且邻格有这种残墙时，战术分支会立刻就近修。没有「把工人石头交给开拓者再建墙」的接口。

**升级券名与默认价**（商店快照有报价则用报价）：

| 对象 | 1→2 | 2→3 |
| --- | --- | --- |
| 武器 / 基地 | `WeaponUpgradeVoucher1` / `StationUpgradeVoucher1`，100 | `…Voucher2`，150 |
| 墙 | `WallUpgradeVoucher1`，20 | `WallUpgradeVoucher2`，30 |

选升级目标：等级更低 → 更靠进攻方向 → 血更低（升级回满血）→ 电磁优先于火箭/加特林（火箭炮有冷却、攻击频率低，升级收益不如电磁炮兑现得快）。墙不要求先修到 80% 再升。

## 5. 武器升级日程

首日主目标是 **一门 2 级 + 最低生存墙**，不是每回合重算「还能不能升级」。三门基础武器建成后，由跨回合持久的 `opening_stage` 推进第一门升级；cycle ≥ `FIRST_UPGRADE_CUTOFF`(40) 且金币仍不够、也没有券，则一次性切到修墙，当天不再回到筹资。

第一天不实现第二门升级。`weapon_upgrade_due`：

| 天数 | 升什么 |
| --- | --- |
| 第 0 天 | 只升一门到 2 级；完成后或截止点资金不足，立即修最低生存墙 |
| 第 1 天 | 先再升一门到 2 级；墙不到 12 段则暂停继续升；三门都到 2 级后先升一次基地，再往 3 级升 |
| 第 2 天起 | 基地仍是 1 级则优先买基地券（白天拿着，挨打/火箭冷却再用）；围住炮和基地的内层墙按能否完工回炮决定，不强求铺满；否则未满 3 级的炮继续升 |

**谁去买券**

第二天起调用 `pick_weapon_voucher_buyer`。第一天只指定一名最近商店的存活工人/开拓者买第一张券，不并行第二张。开拓者只有自己被选中才去商店。

缺钱工人：

`C = 到小贩 + 出售 + 到商店 + 购买 + 到建筑 + 使用 + 用券后回炮 + 耽误原工作`

已持券：只算走到目标建筑、使用和回炮。已有 `kind=weapon` 任务的人保持粘性，除非阵亡、路径不可达或赶不上安全截止。

- 开拓者正在做 `phase_task` 不中断。  
- 金币不够时只有背包矿石能补缺口的工人才计入（开拓者不卖矿）。  
- 工人在正面墙缺口未补时，耽误施工加罚；开拓者身旁有可接任务时加罚。  
- 回炮从**用券位置**算；找不到回路则不派。  
- 行程加回防缓冲赶不上 `T_安全截止` 的人不派。

墙券、基地券在前两天低于武器。第三天起：内层墙和基地 1→2 高于新的武器升级。已站在商店格子上的人优先买武器券，避免邻格工人抢单、开拓者改去买药。

基地 `StationUpgradeVoucher1`：白天基地满血且没挨打时先拿着；机器人贴到基地（观测距离 ≤2）或基地已掉血、或火箭冷却走得及往返时再 `use`，升级回满血。冷却不够走一趟则留在炮位开火。这是策略时机，不是官方「必须此时升级」。

## 6. 第一天白天（官方 cycle 0–69；cycle ≥ 70 入夜回防）

`plan_opening` 是第一天工人主任务的唯一所有者，实现为五阶段有限状态机（`src/agent/opening_schedule.py`）。只统计 `health > 0` 的武器和墙。三炮未齐时才规划开拓者任务；角色处理顺序先开拓者后工人。`opening_stage` 跨回合持久，禁止每回合按瞬时条件在筹资和修墙之间回退。

合法转换：

```text
BUILD_WEAPONS → FUND_FIRST_UPGRADE
FUND_FIRST_UPGRADE → APPLY_FIRST_UPGRADE | BUILD_SURVIVAL_WALL | MUSTER
APPLY_FIRST_UPGRADE → BUILD_SURVIVAL_WALL | MUSTER
BUILD_SURVIVAL_WALL → MUSTER
```

禁止 `BUILD_SURVIVAL_WALL → FUND`、`APPLY → FUND`、`MUSTER → 任何白天经济阶段`。第一天不跑第二门升级，也不调用 `profitable_mine`。

| 阶段 | 工人只允许 |
| --- | --- |
| `BUILD_WEAPONS` | 建三门初级火箭、去施工位、必要回避。禁止采矿和修墙 |
| `FUND_FIRST_UPGRADE` | 采最近可达铜/铁、去 vendor 卖铜铁、去 weaponShop 买第一张券、持券去武器。禁止采石、修墙、自由选矿 |
| `APPLY_FIRST_UPGRADE` | 持券者走向目标武器用券；其他人保持安全位置或回基地，不跨图采石。快照确认一门存活武器 2 级后立刻进墙阶段 |
| `BUILD_SURVIVAL_WALL` | 采最近可达石矿、修最低生存墙、必要时丢掉阻塞容量的铜铁。禁止重新采铜铁和升级筹资 |
| `MUSTER` | 走向分配武器并保持。禁止采矿、出售、购买和远距离施工 |

`opening_time_budget` 只从当前 `opening_stage` 派生允许项，不再用估算在筹资和修墙之间切换。cycle ≥ 40 且金币不够、没有券 → 永久 `BUILD_SURVIVAL_WALL`。剩余白天 ≤ `MUSTER_BUFFER`(3) 或贴身威胁 → `MUSTER`。

资源目标按每名工人到所有可达候选矿的真实最短路径选择：`score = path_length`；服务器已给出单位售价时才用 `path_length / known_unit_value`。`switch_penalty = 4`，且必须落在合法换目标白名单里。每个工人的 `opening_worker_goals` 跨回合保持；连续三回合路径不缩短才宣布原目标失效。检测到 `A→B→A` 时保持原目标、走当前 BFS 下一步。

**修墙先囤够一批再动身（`opening_wall_work`）**：背包里有石头不代表立刻去建墙——只有满足「背包已满」「攒够 `min(STONE_BATCH, 当前缺口数)` 块」「石矿已经不可达」三者之一才会转去 `claim_opening_wall`。否则继续囤，避免变成「采一块、跑回去建一道、再跑回矿点」的单趟搬运。修墙阶段第一天不做第二门升级，背包里只要还有铜铁（不等背包塞满）就立刻去卖，卖不出去才 `drop` 腾位置。

`go_mine` / `liquidate` / `replenish_walls` / `muster_for_night` 只提供原子动作，不能自行改战略阶段。最终命令之后只有紧急治疗、近敌战斗、正式回防可以覆盖。

最低生存墙（`survival_wall_plan`）先封正面通向基地/武器/操炮位的缺口，再补两侧端点。死亡墙、死亡武器不计入完成。

**个人回防截止点，不是全队统一 `MUSTER`**：`opening_stage` 到 `MUSTER` 只是最终兜底（剩余白天 ≤ `MUSTER_BUFFER` 或贴身威胁）；在那之前，每名角色按自己到已分配武器的真实路程单独判断——`remaining ≤ own_travel + MUSTER_BUFFER` 就先于全队进入个人回炮，基地附近的人不会被最远的队友拖累提前停工。背包还有铜铁、且回防前最后一次绕去小贩卖掉还来得及（`remaining ≤ role_deadline + 2×小贩往返 + 1`）时，会先卖再回炮，不会把资源原样带进夜里浪费；真到了硬截止点就不再绕路，直接回炮。

### 开拓者首日

1. 三炮未齐：可接开拓者任务；三炮齐后不再让任务覆盖买券。  
2. 只有自己被选为买券者且金币够才去商店；已持券则去用。  
3. 否则让开墙线/炮位，无事去已分配炮位。  
4. 绝不 `collect` / `build`。

### 工人首日

三炮未齐：金币每座 25，走到空炮位 `build rocket`。没金不改去修墙。

三炮齐后只执行当前阶段的一种主资源目标。背包满才去 vendor；金币够才去商店；获券后去武器。没有指令则记录 `worker_state` / `no_command_reason`，不允许无原因 IDLE。

首日工人 **不走** `muster_for_night` 的第 50 回合一刀切。高压/贴身威胁除外。

## 7. 第二天及以后的白天

`plan_day` 先开拓者后工人，共用同一笔金币预算。

### 工人顺序（`decide_worker_day`）

1. 低血紧急治疗。正面紧急封堵。  
2. **入夜清包窗口**：能卖完再回防时，先卖掉可卖矿，再买/用武器升级券，然后才回防。  
3. 回防（第 9 节）。按 `T_安全截止` 与回炮工时比较，没有第 50 回合一刀切。来不及卖完则带着矿回炮。  
4. 已持武器券或紧急修墙包才继续商店任务；未买的修复包会释放。缺墙时未买的升墙/基地任务让路给新建。  
5. 若应由工人买武器券：开工并买/用；金币不够则先卖矿。  
6. `replenish_walls(..., primary_only=True)`：当前阶段还缺墙，**优先于升墙和修墙**。清包窗口内只保留迎敌紧急封堵。第三天起内层墙提到新的武器升级之前：缺段若本阶段能建完并回炮才铺，工时不够不强求包围。  
   - 缺石：专程去石矿（`pick_mine`，一人一矿+粘性），不改去挖铜铁。石矿不可达或背包满则放弃本步。身上有石转去施工时释放占矿。  
   - 正面迎敌列（`wall_priority==0`）有缺口：有石就建，不等白天末段。8/12 段上限不能代表正面已经有效。  
   - 正面已封、只剩侧翼/外层：该工人回炮工时不够则留石不建（`allow_build=False`）。`overrun` 只在本昼已经安排施工却入夜仍缺墙时 +2，缺石/采购抢占/不可建造单独记，不当成工时低估。  
   - 夜里满足试探外出条件后：按白天逻辑施工。  
7. 其它卖矿触发（第 8 节）。卖矿往返用同一套 `T_安全截止`，试探外出期间仍查返程。  
8. 机会性商店任务：阶段墙没建完则不新开墙/基地升级。修墙包不再在缺墙时插队去商店买。  
9. 三炮齐后，可补外层（需外层准入；`primary_only=False`）。清包窗口内不扩建。非完整施工窗时 `pick_build_target` 只选正面格。  
10. 战术：炸弹 / 眩晕 / 召唤令。  
11. `try_build`：先补武器到 3 座（随时），再按上面的施工窗用石头建墙。清包窗口内不走这一步。  
12. `profitable_mine`：一人一矿，粘到背包满、清包窗口、矿种不再需要或不可达才换。另一人已占的矿降权，全图只剩一座同类矿时仍可分享。分数按本趟真正采得完的数量：`min(剩余格, MINE_TRIP_CAP, 入夜/清包前还能采几下) × 报价 / (去程寻路 + 采集 + 回小贩寻路 + 1)`。新闻只记推断，不指挥采矿或囤矿。当前阶段石头已经够墙缺口时，不再采石。背包满停止。清包窗口内停止采矿并清掉占矿。`replenish_walls` 与开局采石走同一套 `pick_mine`。 
13. 自救或路过买药（不专门跑一趟，避免在商店排队）。

### 开拓者顺序（`decide_pioneer_day`）

1. 低血紧急治疗。  
2. 无进行中 `phaseTask` 时先评估可行自进化任务并预约目标；已在领取范围且无更高优先阻塞则当轮 `acceptTask`。普通买券/卖矿不能无记录打断预约。  
3. `defense_due` 的真实防守（高压、贴身、夜间未清波、回程+`MUSTER_BUFFER` 不够）可打断预约。占用分成 `returning` / `must_hold` / `free`：只有前两者挡住普通经济任务。已到炮位但无强制留守记 `at_post_no_mandatory_hold`，继续评估买券。`threat_eta_to_base` 是剩余回合（白天 `min(入夜剩余, 可见敌人切比雪夫下界)`），不是绝对回合号。贴着已分配武器视为已到岗，即使站在墙线格上。phaseTask 清空后的 `active` 预约立即释放。  
4. 防守所必需的买券必须带 `defense_critical` 依据（高压/贴身/破口），并计入打断任务预约的机会成本；工人在店则仍优先工人。  
5. 任务耗时：部署回退 `DEPLOY_SOLVE_ROUNDS=9`（Alpha/Beta 领取到提交的观测，含探查/修复/验收/提交，不是优化目标 6）。API 用单独的 `API_SOLVE_ROUNDS=9`。领取前不知题型，取各类回退与经验的保守上界。有同类归档样本时用含失败/超时的 p75，且不低于该类回退。两条约束分开：`预计完成 ≤ timeoutRounds`；`去程+预计完成+回程+MUSTER_BUFFER ≤ threat_eta`。`timeoutRounds≥4` 不代表可完成。回程从预计领取站位计算，与 `defense_due` 同一套 `station_return_detail`；已在操炮邻格才允许 0，无炮/无路记未知。  
6. 预约分阶段：前往（`approaching`，由候选有效性维护）、领取待确认（`accept_pending`，等 phaseTask，不重复领取；真实 `defense_due` 仍先回炮）、已领取（`phaseTask`/`active`，不因 isValid 变假去买普通券）。**`phaseTask` 消失后 `active` 视为任务结束，立即 `clear_reservation(phase_task_cleared)`**，不能把过期占用当成永久回防。采购连续无进展是重新评估买家并记录金币不足/挡路/被拒，不默认取消必要购买。`defense_due` 直接读 `defense_snapshot`，与候选回程同一套路径和到位规则。  
7. 宝藏：民间传闻经 LLM 写入 `folkPlan` 并打日志，当前不指挥开拓者买物/`summonTreasure`。自进化占用 `prompt` 时传闻不申请、不消费 LLM。  
8. 战术道具、非武器商店、自救、让开墙线。

每回合无论 `phaseTask` 是否为空，stderr 打一条 `PIONEER_TASK`/`scheduler`（不占 `executeCmd`），记录分支、最终动作来源、候选排除原因、连续采购/回防占用、领取条件、防守与时间筛选来源。`acceptTask` 若在指令合并后消失会记 `accept_overwritten`。

解题在 `PioneerTaskSolver.step`（第 16 节，`strategy.decide` 之后调用一次）：单一入口，既消费上一回合反馈也生成本回合动作，不再拆分成两步。`server.py` 调用后把 `solver.session` 写回 `state.task_session`；`pioneer_schedule.py` 的 `scheduler_task_session` 读它时会自己核对 `key`/`fingerprint` 是否还对应当前 `phaseTask`，过期就当空会话处理，不会让 `solver_ready_to_submit` 把上一个任务的"已可提交"状态带到新任务里。官方清空 `phaseTask` 时直接清空会话，不归档，**不把清空当成判题通过**。每天 LLM 限 3 次（新闻/宝藏），自进化解题不计入这个额度。

## 8. 卖矿

只卖背包里的石/铁/铜，不卖券、药、炸弹。无小贩报价时只按数量触发，不假装知道成交价。已承诺去卖的人（`selling_roles`）会卖完；小贩不可达则停止继续采矿。到了小贩一格内，同种矿一次卖完。卖矿往返达到 `T_安全截止` 则取消；找不到回路不批准这趟外出。夜间未达试探外出条件也不外出卖。

**留石**（仅工人）

- 第一天：每人大约留 4 个（按缺口和工人数分摊）。  
- 第一晚后：当前阶段还缺几段墙，就在工人之间留够那么多石头，只卖超出的。  
- 基地血量 < 满血 70% 时留石降到至多 1 个。  
- 背包 ≥90% 时不再因「囤货」卡住不卖。  
- 新闻要求囤的矿，不在涨价窗口内则先不卖。  
- **入夜清包**：正面迎敌缺口已封时，连石头也卖掉；还有迎敌缺口则继续留石给紧急封堵。

**两种模式**

- **急用立即变现**：筹资目标 = 本次必要采购实际价格（`next_weapon_voucher_cost`）。第一天看全队现金加所有存活工人铜铁估值，不要求某一个工人单包够券价；缺报价仍去卖，成交金币以服务器下一帧快照为准。低血携矿；涨价窗口对应矿。  
- **不急用则批量**：背包过半，或剩余空位 ≤2，或再采一趟就会错过回防前这一趟。不再用「估值≥10 / 6个 / 背包20% / 白天20–70清仓 / 基地<80%」任一即跑。  
- **入夜前清包升炮**：卖掉再回防还赶得上、但剩余安全时间已落入 `PRE_NIGHT_CASHOUT_LEAD`(12) / 第三晚前 `PRE_NIGHT3_CASHOUT_LEAD`(20) 时，不管背包满不满都去小贩清掉可卖矿，并优先买/用武器升级券。来不及卖完再回防则放弃这趟，直接回炮。清包窗口内不再采矿、不扩建非紧急墙。

已经站在小贩旁边则就地卖掉可卖矿。到了一格内，优先卖「数量×报价」最高的那种，`num` 为该种全部可卖数量。

## 9. 回防与夜间

**高压 `pressure`**：正面已建墙被拆且敌人离基地 ≤7 格，或基地 7 格内 ≥4 个敌人，或近敌且基地 <60% 血。

**回防窗 `defense_due`**

$$
T_{\text{安全截止}} = \min(T_{\text{入夜}}, T_{\text{可见敌人首次贴近关键目标}}, T_{\text{其他已知威胁}})
$$

比较：剩余工作 + 工作终点到操炮位 + `MUSTER_BUFFER`(3) 是否仍小于截止时间。切比雪夫只是下界，不是官方移动耗时，也未计入射程。

**首日到位点（观测，不是官方昼夜）**：官方仍是白天 70 / 夜晚 60。观测到约 70–80 机器人在走路，2 级火箭约 76 开火。因此 75/76 只保留为注释，**夜防到位与停止远程经济都按 cycle 70**。无可见敌人不能作为 cycle ≥ 70 后继续裸奔经济的理由。

- 高压、敌人已贴到基地/炮/墙/人员：立刻回，优先于历史空窗。  
- 找不到回路：停止批准新的外出，尝试回炮或处理阻塞；**不可达不等于 8 回合可达**。  
- 满足试探外出条件且当前无相关敌人：不回防，去做有限工作（院内施工、近距维修优先；远矿/卖矿仍查返程）。每回合按当前快照重算，不沿用上一回合的安全结论。  
- 已过该角色到位点且夜间未达试探外出条件：一律回炮（留任务点看 `pioneer_should_hold_task`）。  
- 白天有远处敌人时仍取与到位点剩余的最小值，不会因为敌人还远就推迟夜防。  
- 没有独立炮：先回基地旁边。  
- 首日工人仍不走 `muster_for_night` 的强制集合，由开局计划按返程集合（高压除外）。  
- 开拓者回防窗是否留下由 `pioneer_should_hold_task` 决定。未开始的任务始终不在回防期新接。回炮从任务点算。

`two_guns_can_hold`（夜间）：两名存活工人、两门血量过半的炮；当前看不见敌人、高压/破口、BOSS、2 个及以上敌人、或最近敌人距基地 ≤8，都视为两门炮守不住。白天无可见波次，一律按守不住处理。

**夜间一人一炮**

- 里侧的人开里炮、外侧的人开外炮；已靠在炮边（一格内）的优先。分配会尽量沿用上一回合。只有 `pioneer_should_hold_task` 为真的开拓者不占炮。  
- 去炮：先把队友当障碍寻路，走不通再穿过占位。操控位不落在未来墙缺口上。  
- 已在炮一格内：火箭冷却则守着；否则打射程内目标。优先级 BOSS > 大 > 中 > 小，同级打血低的。加特林/火箭的 `targetPos` 个数等于武器等级。  
- 高压时先扔包里的炸弹/眩晕，不离开炮位去商店（`allow_travel=False`）。  
- 没有分配到炮、也没有其它指令时，最后自救。

**试探外出 `night_wave_cleared`**：官方没有一夜单波或清波标志。8 只是未经验证的策略参数，只能叫「满足试探外出的条件」，不能叫确认清波。本夜见过威胁后，连续 `WAVE_CLEAR_STREAK`(8) 回合快照里没有存活敌人才允许有限外出。**当前出现相关敌人立即清零空窗、撤销外出、重算回防。** 开局空波次（还没刷过怪）仍守炮。每个白天开始清掉该标记和空窗计数。

**就近施工 `night_near_work_allowed`**：见过威胁、当前无怪、连续空窗 ≥ `WAVE_LOCAL_STREAK`(3)、且尚未达到清波阈值。此时已在炮旁（切比雪夫 ≤1）的工人可补紧挨着的正面墙或就近维修，不离开炮去采矿。

敌对判定：`health > 0` 且 `target_team` 空或等于我方。

## 14. 持久化与日志

`state/build_memory.json`：失败建造点、工人建造目标、商店任务、上一回合指令、`policy_memory`（武器分配、卖矿承诺、开局「只修墙」、召唤日限额、新闻/宝藏记忆、正面墙是否被拆过、角色存活标记、工人占矿目标等）。队伍/地图/基地变化或回合回退时清空策略记忆，并重置新闻记忆与解题会话。协议没有比赛 ID，无法区分「同一队伍连续两局都从 round 0 开始」。`worker_item_jobs` 会随记忆落盘。

**阵亡与复活都要清理，不止复活这一侧**（`tactics._note_respawns`）：工人/开拓者从存活变阵亡、或从阵亡变存活时，都会清掉该角色名下的 `worker_build_targets`、`worker_item_jobs`、`weapon_assignment`、`opening_wall_targets`、占矿目标、`selling_roles` 预约。这不是为了好看——`_pending_item_job_targets`（道具任务目标去重）和 `claimed_mines`（占矿降权）都不检查角色死活，如果死者名下的任务/占矿条目一直留着，队友永远没人会替它释放，等于永久卡住一个武器升级目标或一座矿。

自进化只有一份状态文件，换任务不清经验：

| 文件 | 内容 | 清理 |
| --- | --- | --- |
| `state/task_session.json` | 当前任务：识别到的路径、已读文档、历史动作与结果、答案、调用次数、重试次数 | `phaseTask` 清空时直接清掉，不归档 |

决策原因写在 `logs/` 的 decision 报告里。自进化每个任务还会在 stderr 打 `PIONEER_TASK` / `task_summary`（实例、prompt 哈希、领取/提交回合、拦截次数、结束原因）。动作合法不等于答案判对。

本地校验（`BasicActionValidator`）只拦能确定的字段错误：未知动作、缺 `targetPos`、越界、`attack` 缺操控者、`summonTreasure` 缺物品、`submitAnswer` 缺答案、升级券/炸弹/眩晕/修墙包缺目标等。不能代替官方合法性。

## 15. 刻意没做或未证实

- 开拓者采矿/建墙（官方角色限制）。  
- 背包物品转交。  
- 墙线、炮位等于官方可建造区（未证实）。  
- `roundNo` 从 0 还是 1 起算（换边/回退已按队伍、地图、基地和回合回退清记忆，但没有官方比赛 ID）。  
- 机器人是否会直接拆墙、外层开口是否真能分流（日志写了「需回放验证」）。  
- README 里部分条目已过时（例如「升级优先补墙」「眩晕未实现」），以本文和代码为准。
- 自进化平台是否另有任务实例 ID（当前只有 type/position/`timeoutRounds`）。
- `timeoutRounds` 从领取还是任务开放起算；本地截止回合标为估计值。
- `phaseTask` 清空是否等于判题通过（当前不记录，直接清空会话）。
- 求解器（`task_solver.py`）是刻意回退过的简化版：不做 API 分页/去重、不拦截重复失败命令、不做部署 CRLF 自动修复、不跨任务保存已验证经验。这些能力在更早的历史版本里出现过，代价是复杂度和对 `python3` 沙盒环境的依赖（比赛沙盒是否保证 `python3` 未经确认），权衡后退回纯 `sh` 脚本。
- 提交确认（`errorCode` 2/4）判断没有按角色/动作过滤：协议本身 `ErrorInfo` 只有 `errorCode`+`description`，不带角色归属，理论上同一回合其它角色的非法动作触发的 `errorCode 4` 可能被误判成这次提交被拒绝。

## 16. 自进化解题（PioneerTaskSolver）

入口：`PioneerTaskSolver.step(state, commands)`（`src/agent/task_solver.py`），`strategy.decide` 之后调用一次，既消费上一回合反馈又生成本回合动作。HTTP 协议和角色指令格式不变。

这是**刻意回退过的简化版**：本轮删掉了 API 分页/去重、重复失败指纹拦截、部署 CRLF 自动修复、跨任务经验持久化与归档（`task_experience.json`/`task_archives.json`）这些更早期加过的能力，换回一套只依赖 `sh`（不依赖 `python3`）的最小状态机——比赛沙盒是否保证 `python3` 可用未经确认，这台开发机上就踩过 `python3` 被系统占位程序劫持、真实解释器缺失的坑，纯 `sh` 脚本更保险。旧版本的这些能力仍在 git 历史里（`git log -- src/agent/task_solver.py`），需要时可以参考，但当前代码没有。

### 会话与阶段

`self.session`（落盘到 `state/task_session.json`）跨回合持久，字段：`key`（`[teamId, type, phaseTask]`，判断是否换了新任务）、`stage`、`paths`/`index`/`offset`（待读文档列表与进度）、`documents`/`history`（已读内容与动作历史）、`calls`/`retries`、`taskKind`/`workspace`（`task_context` 解析结果）、`answer`。协议没有任务实例 ID，`key` 换了或 `round_no` 回退就直接开新会话，不归档旧的。

阶段流转：`read → wait_read → (read，还有下一页/下一份文档 | ask，文档读完)`；`ask → wait_llm`（发 prompt，`calls` 满 12 次后进 `exhausted`，不再问）；`wait_llm` 解析 LLM 返回的 `read`/`execute`/`submit` 动作，分别转回 `read`、转 `tool → wait_tool → ask`、或转 `submit → wait_submit`。运维任务点了相对路径的文档但还不知道 `workspace` 时，直接跳过 `wait_read` 进 `ask`，先问清楚工作区在哪。同一回合重复调用返回缓存的 `response`，不重复推进状态机。

`_holding_for_output`：开拓者本回合命令是 `move`/`attack`/`buy`/`sell`/`drop`，或正操控某门炮（`controllerId` 匹配），则不「持有」解题权——仍会消费已经收到的沙盒/LLM 回传更新会话，但不会新发探查/LLM/提交指令，避免和回防/操炮的移动指令打架。

### 沙盒脚本

`READ_SCRIPT` / `EXEC_SCRIPT` 都是纯 `sh` 脚本，通过 `sandbox_command` 包成 `sh -c '<script>' -- <参数...>` 执行，参数逐个 `shlex.quote`。

- **读文档**：`workspace` 给了就先 `cd`；文件存在就 `readlink -f` 取绝对路径，否则在当前目录和根目录下 `find`（排除 `proc/sys/dev/.git/__pycache__`）按 basename 找，最多留 10 条候选。**必须恰好 1 个匹配**，0 个是 `not_found`，多个是 `ambiguous_path`。命中后用 `dd`+`awk` 从 `offset` 读最多 6000 字节，转义反斜杠和引号，回报 `nextOffset`/`more` 供分页续读。
- **执行命令**：`workspace` 给了就先 `cd`；`timeout 10 sh -c "$command"`，输出截到 6000 字节，超时（退出码 124）标 `tool_timeout`。

沙盒结果靠 `marker=PIONEER_TASK` + 本次的 `requestId` 匹配；找不到匹配结果时 `wait_read` 最多重试 2 次（重发同一条 `pendingCommand`），`wait_tool` 找不到就直接记 `sandboxError` 并转 `ask`——没有更细的「未返回/超时/无关内容」区分。

### 提交确认

`wait_submit` 阶段：本回合出现 `error_code` 属于 `(2, 4)` 的错误，**或**开拓者这一回合的 `lastRoundRoleActionResults` 为 `False`，就判定提交被拒（记 `submissionRejected` 到 `history`），转回 `ask` 重新求解。没有第三种「未知，继续等」状态——不满足拒绝条件就默认还在等，下一回合再看。

`errorCode` 判断**没有按角色/动作过滤**（协议里 `ErrorInfo` 只有 `errorCode`+`description`，不带角色归属）：如果同一回合恰好有别的角色因为别的原因触发了 `errorCode 4`，理论上会被误判成这次提交被拒绝。这是简化版的已知限制，不是遗漏。

### Prompt（`make_prompt`）

固定的一段中文说明（任务类型不限、taskKind 只是启发式线索、API 任务要求先读任务点名的 `API_DOCS.md`、部署类要把修复和验证合并成一条 `execute`、只返回一个 JSON 对象等）+ **始终原样拼接**的 `DEPLOYMENT_SOP`（来自 `task_sop.py`，不管 `taskKind` 是不是 `workspace` 都会带上，不像更早版本那样按分类只注入对应 SOP）+ 当前任务的 JSON 证据块（`task`/`taskKind`/`workspace`/`documentPaths`/`documents`/`history[-16:]`）。

没有失败去重、没有调用经验复用——每次问 LLM 都带着最近 16 条历史，重复犯错与否完全靠 LLM 自己从历史里看出来，代码不拦。

回合预算：只有一个硬上限——`calls`（LLM 调用次数）到 12 次就 `exhausted`，之后不再发 prompt。没有基于 `timeoutRounds` 的截止回合估算，那部分完全由 `pioneer_schedule.py` 自己算（`estimated_solve_rounds`/`KIND_FALLBACKS`），彼此独立。
